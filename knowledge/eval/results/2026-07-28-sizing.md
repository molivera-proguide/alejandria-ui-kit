## Findings → fixes (input to loop step 4)

- **G4 — ficha `MetricCard` no longer stretches.** The four ficha tiles (TAREAS/ALERTAS/UNIDADES/
  RIESGO) render as compact, content-sized boxes instead of the baseline's full-width stretched
  tile. Confirms `.ds-metric--ficha { width: fit-content }` (added this session) holds under a
  real Cursor build + real browser, not just the Storybook headless check. No further fix needed
  here.
- **G4 — `LineChartCard` no longer fills the viewport.** The "ACTIVIDAD POR MES" chart sits in its
  own bounded box, doesn't dominate the panel. Confirms `.ds-chart-card { max-width: 280px }`
  (added this session) holds. No further fix needed here.
- **G1 — kanban columns no longer show the baseline's empty space, despite `TaskCard` getting no
  code change this session.** The fix applied here was documentation-only: `anti-examples.md` §7
  was updated to explicitly resolve the component-vs-composition boundary ("cap a kanban column to
  ~the card width" is the consumer's job). This run's columns look sized to their card's content,
  not to a wide `1fr` grid track. **Tentative, not confirmed:** this could be the agent following
  the updated guidance, or just this run's own composition choice — can't tell without the code.
  If it holds across repeat runs, it's evidence that a documentation fix alone (no CSS change) can
  close a sizing gap when the component already self-caps correctly.
- **G5 — `Asistente` 774px freeze confirmed still present**, at roughly the expected fixed width
  regardless of the (much wider) browser viewport. Matches the already-tracked, deliberately
  deferred item in `component-roadmap.md`. Not a new finding; no action taken.
